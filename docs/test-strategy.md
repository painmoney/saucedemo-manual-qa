# Стратегия тестирования

## Цель

Проверить основной пользовательский путь SauceDemo и подготовить прозрачные артефакты ручного тестирования для публичного QA-портфолио.

## В области тестирования

- авторизация публичных тестовых пользователей;
- каталог и сортировка товаров;
- карточка товара;
- добавление и удаление товаров из корзины;
- валидация данных при оформлении;
- обзор заказа, расчёт итогов, завершение и PDF-чек;
- основная навигация и боковое меню.

## Вне области тестирования

- реальные платёжные системы;
- серверная часть, база данных и API;
- полноценный аудит безопасности, производительности и доступности;
- кросс-браузерная и адаптивная матрица;
- переходы во внешние социальные сети, кроме проверки наличия ссылок;
- проверка по формальной спецификации — она не предоставлена.

## Подход

- Риск-ориентированное тестирование с приоритетом авторизации, состояния корзины, цен и оформления.
- Семь репрезентативных сценариев выполнены отдельным контрольным прогоном.
- Чек-лист из 57 пунктов предназначен для регрессии. Наличие пункта в чек-листе не означает, что он выполнен в текущем прогоне.
- Подозрительное поведение без подтверждённого требования оформляется как аномалия с вопросом владельцу продукта, а не как подтверждённый дефект.

## Статусы

| Статус | Значение |
|---|---|
| Пройден | Фактический результат совпал с ожидаемым |
| Не пройден | Фактический результат противоречит подтверждённому требованию |
| Заблокирован | Проверку невозможно продолжить из-за окружения или зависимости |
| Не запускался | Для текущего прогона нет доказательств выполнения |
| Наблюдение / нужны требования | Поведение воспроизведено, но классификация зависит от неподтверждённого правила |

## Критерии начала

- SauceDemo доступен.
- Публичные тестовые данные известны.
- Начальное состояние корзины очищено или явно зафиксировано.

## Критерии завершения

- Для всех семи тест-кейсов указан подтверждённый результат.
- Для каждой аномалии есть шаги, фактический результат, предположение об ожидаемом результате и вопрос по требованиям.
- Все ссылки на доказательства работают внутри репозитория.

## Риски

| Риск | Мера |
|---|---|
| Демо-приложение изменяется без уведомления | Фиксировать дату и точные наблюдаемые значения |
| Корзина сохраняет состояние между сценариями | Явно очищать корзину перед сценариями с нулём товаров |
| Нет бизнес-требований | Разделять факт, предположение и вопрос владельцу продукта |
| Время в имени чека отличается от локального | Сохранять исходный PDF, использовать стабильное имя файла |
