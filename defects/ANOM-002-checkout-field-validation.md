# ANOM-002 — форма оформления принимает пробелы и неправдоподобные значения

| Поле | Значение |
|---|---|
| Тип | Аномалия валидации / требуется уточнение требований |
| Статус дефекта | Не подтверждён |
| Серьёзность, если поведение непреднамеренное | Minor–Major, зависит от дальнейшего использования данных |
| Предлагаемый приоритет | Medium |
| Воспроизводимость | Воспроизведено с двумя наборами данных 22.10.2026 |
| Окружение | SauceDemo; `standard_user`; встроенный браузер ChatGPT, версия не зафиксирована |

## Краткое описание

Форма проверяет только наличие символов. Она приняла по одному пробелу в каждом обязательном поле, а также `1` в First Name, `@` в Last Name и `ABC` в Zip/Postal Code, после чего открыла обзор заказа.

## Предусловия

1. Выполнен вход как `standard_user`.
2. В корзине есть хотя бы один товар.
3. Открыта форма данных получателя.

## Набор данных A

1. Ввести один пробел в First Name.
2. Ввести один пробел в Last Name.
3. Ввести один пробел в Zip/Postal Code.
4. Нажать **Continue**.

### Фактический результат A

Открывается обзор заказа. Ошибок обязательных полей нет, хотя после удаления пробелов значения пусты.

## Набор данных B

1. Вернуться на форму.
2. Ввести `1` в First Name.
3. Ввести `@` в Last Name.
4. Ввести `ABC` в Zip/Postal Code.
5. Нажать **Continue**.

### Фактический результат B

Открывается обзор заказа без ошибки валидации.

## Ожидаемый результат — частично неподтверждённое предположение

- Сильное предположение: пробелы по краям удаляются, а фактически пустые обязательные поля отклоняются.
- Зависит от требований: имена отклоняются, если нарушены заданные ограничения по длине или символам.
- `ABC` отдельно не считается дефектом: буквенные почтовые индексы существуют, а поддерживаемые страны не указаны.

## Возможное влияние

- непригодные данные получателя в заказе;
- проблемы в доставке, поддержке и аналитике;
- обход обязательности полей с помощью пробелов.

3. Какие страны и форматы почтовых индексов поддерживаются?
